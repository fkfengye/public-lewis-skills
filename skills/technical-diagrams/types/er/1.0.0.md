# ER 图语义契约 1.0.0

适用于概念实体关系、逻辑数据模型和物理表关系。先确认本次模型层级；DDL、迁移脚本、字段说明及用户规则是语义来源，参考图只提供视觉依据。截图不完整的字段或约束标注待确认，不补造字段、外键、唯一性、级联操作或业务阈值。

## 实体、字段与约束

- 模型分别记录实体/表、字段及数据类型、可空性、PK、UK、物理 FK、普通索引与关系。先按来源中明确声明的数据库方言解析 DDL，包括方言规定的隐式约束；缺少信息且无法从该方言确定时才用 unknown，不凭经验补造数据库类型或 NOT NULL。例如来源明确为 PostgreSQL 时，PRIMARY KEY 隐含非空，普通字段省略 NOT NULL 则允许 NULL。记录推导依据，不把“未逐字写出”误当成“无法确定”。
- 复合 PK / UK / FK 以完整字段组记录并在图例或表下注明；不能拆成多个单列约束。业务标识并非自动成为唯一键，逻辑关联字段也不自动加 FK 标志。
- 详细物理模型保留来源中的类型、长度、精度及约束；总览可按用户要求选择关键字段，但明确省略范围。长字段名换行或扩容，不能用省略号隐藏约束。

## 关系与记法

- 每条关系记录 `kind`（`logical_reference` / `physical_fk` / `association`）、引用端字段组、目标端字段组、条件、证据与两端基数。物理 FK 必须有 DDL/迁移/明确约束定义的证据；同名字段或查询 JOIN 不足以证明 FK 存在。
- 使用引用箭头时，方向为“引用字段 → 被引用字段”。箭头不表示基数、数据流、执行顺序或约束强度。逻辑引用可用虚线，物理 FK 用实线，并给出本图图例；参考图覆盖线型时同样必须标明含义。
- 鸟爪或 `0..1 / 1 / 0..* / 1..*` 基数记法只能依据明确来源，也可由有证据的 FK、目标唯一性、引用字段可空性与业务约束推导；两端分别记录依据。单列可空 FK 指向 PK 且引用列非唯一时，每条引用记录可对应 0..1 条目标记录，目标记录可对应 0..* 条引用记录。未知基数不猜一对多，使用“基数待确认”旁注。不要混用未解释的箭头和鸟爪。
- NULL 是字段约束，可选性与基数是关系约束。可空单列或复合引用不自动等于一条可选外键关系；非空逻辑 ID 也不保证目标记录存在。复合 FK 的空值匹配规则以实际数据库/DDL 为准，未知时不推断。
- 条件引用单独写 `condition`，在线旁标注触发条件。例如 `source=CACHE` 才使用某引用，不把它画成所有记录都必须满足的 FK。多对多是否有连接表由来源决定，不因排版擅自新增表。
- **线旁标签必须同时给出关系名与基数比例**（如「选课学员 1 : 0..*」），比例写法与两端依据按本图图例统一；基数不得只集中列在图例或注记卡里。未知基数写「基数待确认」，不猜一对多。标签与线条分配独立空间，几何变更后重新核看标签位置。

## 排版与验收

表头、字段、类型、键/可空性和说明分区；总览可合并约束与说明列。实体之间留出走线槽，引用优先连接对应字段行的独立端口。绕外侧时保留字段端点，并在标签或 metadata 中明确字段映射，不能把线停在说明卡上。

同一对表多条引用分别使用端口和通道；交叉时调整表顺序、外侧通道或分图，不以长曲线穿过表格和文字。表行分隔线属于网格，不是关系连接；关系路径使用 `data-diagram-role="connector"` 以便几何检查。

计数上限、有效期、缓存规则、排序优先级等是业务旁注，不画成新实体或关系。通用示例里的表名、条件及数值不得自动带入其他任务。

验收逐项核对实体/字段、约束组、关系方向、关系类别、条件及基数证据，并核对每条关系线的线旁标签都含关系名与基数比例；对比模型确认风格切换没有改变其中任何一项。

## 最小模型形式

```json
{
  "type": "er", "level": "logical",
  "entities": [{"id": "execution_log", "fields": [{"name": "snapshot_id", "type": "unknown", "nullable": "unknown"}]}],
  "relationships": [{
    "from": {"entity": "execution_log", "fields": ["snapshot_id"]},
    "to": {"entity": "artifact_snapshot", "fields": ["snapshot_id"]},
    "kind": "logical_reference", "condition": "source=CACHE",
    "cardinality": {"from": "unknown", "to": "unknown"},
    "evidence": "本次任务提供的逻辑引用说明"
  }]
}
```

此片段只演示字段与关系结构；完整模型必须包含所有被引用实体与字段，并检查端点确实存在。
