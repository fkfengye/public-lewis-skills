# 架构图语义契约 1.0.0

模型包含系统/模块边界、组件、存储和跨边界协作。区分现状、拟新增、拟改造；职责分组不代表新增部署单元。数据表只按来源列出，不因复用旧图样式遗漏新增实体。

默认自上而下分层，入口/编排/业务服务/网关/外部系统按任务实际职责排列。若系统并非此顺序，不套固定业务层级。持久化层保持所属服务边界，跨服务直接访问数据库需有来源依据。

线标明调用目的/协议或数据关系，读写、请求和异步回调有清楚区分。回调沿外侧独立返回通道；两条独立业务链可分列，避免跨图大对角线。总线仅用于共享通道，不把邻近关系画成真实调用。

核对每个名称、接口、表和箭头端点；共用发送组件不代表不同报文必经同一具体接口。必要时拆架构总览与模块细节，不能因画布限制省掉系统边界或关键组件。
