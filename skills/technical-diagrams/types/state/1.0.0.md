# 状态图语义契约 1.0.0

先固定真实状态集合，分别列事件、守卫条件、动作与迁移。状态是可持续的业务条件；“更新缓存/写审计/计数+1”通常是动作或副作用，不自动成为第五种/额外状态。

开始点与第一状态之间标明触发事件。各结果状态尽量同层对齐，迁移方向明确。自循环只用于允许事件后仍留原状态的情形；只读查询可作为旁注，不因方便画线而增加状态转移。

主分支可使用总线/正交分叉，各标签置于线旁独立区域。正常迁移与自循环分通道，自循环入点和出点分离，避免巨大的泪滴曲线包围无关状态。

状态框与动作/旁注形状可区分，但不要依赖颜色区分业务含义。终态能否修正、重复事件是否幂等、迟到事件是否改变对外状态均依业务模型定义；示例中的处理口径不构成通用业务规则。

验收检查：每条转移能回到模型事件/守卫；没有被美化引入的新状态；旁注与状态节点不混淆；回路方向、标签位置和入口终点清楚。
