适合表达资料、项目或任务经过多个处理节点的流程。白色外画布内可放浅灰填充、细黑实线、轻圆角的系统边界，较大标题位于边界内上方右侧。边界内外的归属、节点数量和流程方向由本次资料决定；实体、存储和用户可直接作为节点，不强制添加起止或判断。实际流程不是示例业务或特定产品的默认模板。

## 视觉形态与文字

使用独立 [tokens.json](tokens.json) 中的低饱和粉、绿、蓝紫、黄和紫色：处理节点为浅蓝紫细边圆角横卡，重点处理节点可使用黑色较粗边框的竖向圆角卡。存储若需圆柱，使用可编辑的完整椭圆顶、直侧边和弧形底，浅绿填充与黑色细描边；形状和颜色不单独证明真实存储或部署语义。

资料可由浅粉、细黑边的竖向圆角容器分组，标题居中并按真实文字换行。小文件图形以真实矢量轮廓呈现黑边、白或淡紫填充、右上折角及折线；组内项目按模型标识排列。若展示重排，前后相同项目须使用一致标识，顺序改变需有来源或示例模型支持；不因风格强行重排、固定文件数或虚构数据。

外部人物可使用自绘的细线头像与肩部轮廓，输入气泡为单层浅黄色椭圆形轮廓和朝向人物的真实尖尾；尖尾是插画，不是流程箭头。输出可用**单层浅紫填充、细黑边、多瓣圆润轮廓**，无深蓝外层或偏移阴影；标签置于云形内部真实可用区域，外部说明与箭头留出空间。人物、气泡及云的存在和语义均由模型决定。

标题、节点、文档、说明和线标签有各自字号；气泡可用斜体并提供可读中文后备。根据实际字体度量扩容与换行，原图字体无法准确辨认时不声称完全一致。

## 连接与边界

有向关系只在真实终点绘制黑色实心箭头；共线无障碍优先直连，必要转折按用户或元数据选择的直角折线、圆角折线或曲线绘制。圆角折线须使用真实弧线，不能为制造圆角而增加本不必要的折点。独立输入、请求、返回和通知按实际模型分开，禁止凭原图默认补造响应或协议。

标签可在线旁或分行，避开线路、箭头、节点和所有边框；不使用遮罩伪造留空。跨越系统边框的业务路径须保留可辨识的端点与归属，路径与框的交点不自动成为汇合节点。非关联连接交叉按交互规范消歧；比较弯折、长度和交叉时语义与端口约束优先。
