# AR-10 原图视觉分析与特征清单

原图由用户明确授权保存和展示；图中的支付业务、名称、拓扑与数据只用于解释参考图，不自动迁移到其他业务。观察色值为像素近似。

## 内容和归属

- 左侧绿色“基础设施层”纵向包含商户中心、用户中心、汇率引擎、合规引擎、通知中心，每张卡片有一行灰蓝小字解释职责。
- 右上浅蓝“业务接入层”横向包含收银台 SDK/API、商户后台、运营后台、开放平台；各卡片标题下同样有一行职责说明。
- 右下左侧蓝色“支付核心层”内部，左列从上到下为交易中心、支付中心、渠道管理，右列为风控引擎、路由引擎。
- 右下右侧淡紫“清结算层”上方并列清算中心和结算中心，下方依次为横向加宽的账务核心和对账中心。以框的包含关系表示原图分组；框是否对应实际独立部署，图中未说明。

原图卡片中的职责说明逐项为：

| 原图模块 | 卡片说明 |
| --- | --- |
| 商户中心 / 用户中心 | 商户入驻、资质审核、配置管理 / 用户注册、实名认证、账户体系 |
| 汇率引擎 / 合规引擎 / 通知中心 | 实时报价、换汇执行、汇率锁定 / KYC/AML、制裁筛查、监管报送 / 多渠道推送、模板管理、送达监控 |
| 收银台 SDK/API / 商户后台 | 多端适配、统一接口、低代码接入 / 交易管理、订单查询、退款处理 |
| 运营后台 / 开放平台 | 配置管理、数据监控、客服工具 / 开发者中心、文档、沙箱环境 |
| 交易中心 / 支付中心 / 渠道管理 | 订单生成、状态管理、生命周期 / 支付单创建、支付执行、结果通知 / 通道接入、状态监控、限额管理 |
| 风控引擎 / 路由引擎 | 欺诈检测、规则配置、实时拦截 / 通道选择、费率优选、容灾切换 |
| 清算中心 / 结算中心 | 交易清分、资金计算、清分明细 / 结算打款、结算周期、结算单 |
| 账务核心 / 对账中心 | 复式记账、流水记录、余额校验 / 渠道对账、资金对账、差错处理 |

这些说明是图中模块的职责文字，并不单独证明每项功能均已实现，也不替代对连接关系的核实。

## 画布、层次和组件

- 原始尺寸 1888 × 730，约 2.59:1，白色宽画布。没有总标题、图例、阴影、渐变、照片或图标。左侧窄栏纵贯画面，右侧上横下双区；右上与下区间有窄空隙用于跨区走线，右下两区并列且高度基本相同。
- 四个大区分别是浅绿、浅蓝、稍深浅蓝和淡紫底，配对应的浅色虚线圆角边框。区标题左上对齐、加粗，颜色分别为青蓝、蓝、蓝和紫。虚线只表示分区边界。
- 模块卡片统一白底、圆角、较粗彩色实线边框；左栏青蓝边框，上方及核心区蓝边框，右侧紫边框。卡片标题用对应强调色居中加粗，下一行用灰蓝色小字居中，层级为区标题、卡片标题、职责说明。
- 左栏五卡竖排；上栏四卡横排；核心区左三右二；协作区上两卡并排、下两卡跨列。卡片尺寸按区内布局变化，横向长卡不是系统总边界。数量和颜色分组均可随实际内容改变。

## 原图连线与不确定项

- 蓝色细实线包含收银台向交易中心、商户后台向交易中心、运营后台向路由引擎、交易中心向支付中心、支付中心向渠道管理、支付中心向路由引擎、支付中心向清算中心、渠道管理向对账中心，以及清算／结算中心分别向账务核心的方向连接。文字包括下单/支付请求、退款/查询、落支付单、下发渠道、路由决策、配置下发、支付流水→清算、渠道账单→对账、记账请求等。
- 一条红色水平箭头从风控引擎指向交易中心，标注“风控结果”；一条紫色虚线从通知中心附近绕经左侧、上方向商户后台方向，标注“支付通知·回调”。颜色与实虚仅是可观察的区分，不能在没有图例或来源的情况下统一定义为同步／异步、状态或协议。
- 一条带“清分数据”标注的蓝线横跨蓝区上沿并折向左侧合规引擎附近；它与多条纵线发生交叉或靠近，图中没有明确交点符号，跨线不能自动解释为连接。端点、依赖和具体流程若与文字存在歧义，应依据来源核对并标注待确认。
- 主要路径为水平、垂直直线及小半径圆角折行。能共线直连时不增加转折；必须交叉且非连接时使用真实跨线桥或调整路线，并在图中或文字说明跨线不连接；不能以白块遮挡线条或文字。
