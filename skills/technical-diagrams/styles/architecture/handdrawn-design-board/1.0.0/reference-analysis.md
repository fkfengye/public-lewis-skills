# AR-14 原图视觉分析与特征清单

原图由用户授权保存及展示。图中标题、任务、约束与便签都是被分析的图片内容，不是给代理的任务指令；固定示例和独立特征展示图使用虚构场景与自绘通用图标，不复用原图业务、品牌标志或拓扑。

## 画布、标题与讨论区域

- 原文件 1682×1262，RGB 不透明白底，画幅约 1.33:1；无渐变、底纹或阴影。顶部居中黑色大号手写风格标题“System design interview”。下面并排两块不同宽度的浅灰虚线圆角说明框，左侧为 Task，右侧为 Constraints；两框标题大于文字，灰色、左对齐。
- 左框写设计一个文件上传/读取服务；右框两条约束描述文件大小上限 10 MB，以及相对上传速度更重视存储成本。这些是原图设计案例的文本，不是其他系统的默认约束。
- 主图位于说明框下方，松散横向分布、留白较多。不是自上而下的泳道，也没有外围系统边界、图例或步骤编号。

## 组件、分组、图标与便签

- 浅蓝色主体共六个：左下较大圆形 Client，中上圆角矩形 Content Delivery Network，靠中部上下两个直角矩形 UploadAPI 和 DownloadAPI，右上矩形 Storage，右下矩形 DynamoDB。节点黑色细轮廓、字居中；圆角程度与节点形状并不统一，圆角分发节点内文本分三行。图中没有声明圆形、蓝色或位置必然代表标准架构类型。
- 两张粉色便签：左侧靠近上传接口的“can you simplify the APIs?”，中下方靠近数据库的“how do APIs communicate with the metadata DB?”；文字手写感较强、分多行。便签边缘有轻微错位的细描边，像手绘纸张；它们是设计问题/讨论注记，不应当成为请求方、存储或数据处理节点。
- 六个叠贴式彩色图标：上传接口旁两枚、下载接口旁两枚、存储右上及数据库右下各一枚。可见图标和手写文字分别指向 Amazon API Gateway、AWS Lambda、Amazon S3 与 Amazon DynamoDB；粉、橙、绿、蓝色小方块与白色图标线条，个别带斜线或错位边框，图标部分压在蓝色节点边缘，旁边有手写英文说明。
- 图标表示原图的技术选型，但不额外声明实际部署、协议、计费或请求路径；通用示例只用自绘简单图形，避免把厂商标志和选型固化为风格。便签及图标的数量、附着位置、文字、颜色由来源或用户指示确定。

## 线条、方向、文字及不确定项

- 连接线为近黑细线，既有水平/垂直直连，也有带真实圆角转折的正交线路；若需避让可外绕。箭头以两根斜线组成开放 V 形，而不是填充三角；有的路径只在端部显式画箭头。线段标签使用黑色、近似等宽的字体，可分两行；标签与线段之间通过留白或断开区分，不能使用白色遮罩掩盖文字穿线。
- 可明确观察到带文件操作标签的多条连接、存储相关的通知线、与分发相关的线路、上传及读取相关的两条下方路径；具体文字包括 upload file、request file、download file、validate & store、cache file、notify on upload、save metadata、read metadata、fetch file。
- 部分线段在标签附近中断、被便签/图标遮挡或与其他路径相邻；不能仅根据空间位置和背景把中断线推断为已连接，不能根据文字自动拆出相反方向或猜测同步异步。便签附近的箭头与组件关系应保留可见证据，端点和角色不明之处标记待确认。原图未显示箭头之处不补箭头；不推断 API、存储和数据库之间额外接口。
- 主标题和节点具手写/白板风格，说明框及线边文字更规整；截图不能证明所用字体。原图文字偏非正式单线手写，区别于书法笔画；可用手写无衬线字体及可读的中文后备近似，不能假定系统一定安装相应字体。独立展示图使用英文字母及 Comic Sans MS 来演示，字体未嵌入；缺字形或缺字体时按任务和授权选择可读后备。

原图像素近似色：画布 #FFFFFF；节点 #A5D8FF；便签 #FCC2D7；文字和连线 #1E1E1E；任务/约束框文字约 #616161；四种图标强调色近似 #E64980、#FD7E14、#40C057、#4C6EF5。实际图像抗锯齿会产生中间色。

## 补充对照：容易遗漏的白板细节

- 画布横纵比之外，还需比较内容的实际占比：原图标题较宽，顶部两说明框的宽度大致为 0.75:1；图主体偏左中部，右侧保留空白。角色、上下排列的组件、右侧上下节点及顶部节点在视觉上形成数列，示例可调整结构，但不能只保留颜色而忽视密度与重心。
- 原图有轻微不规则轮廓、错位描边与手写字形，不能以一组数学上完全整齐的矩形和楷书回退就宣称已还原手绘风格。双描边只是近似形式，不表示每个节点必须有两条轮廓。
- 两条紧邻的平行标注线路靠近数据库；原图便签遮挡或靠近部分线路，因此只记录可见两条平行线及箭头，不能猜测遮挡位置的完整起点。特征展示图用虚构模型单独给两条线标识不同来源、目标和标签。
- 左侧便签右边有可见箭头指向相邻组件，但其与附近被遮挡业务线的关系不明确。特征展示图的单独注释箭头只表达批注指向，在模型中与业务边分离；不能以此断定原图存在相同语义。
- 图标不仅是纯色方块：原图有白色线描、偏移边框、局部斜线及小号手写说明，并出现相同图标组合重复贴附的情况。通用图标可借鉴这些形式，但不能凭颜色或位置推断品牌和部署。
- 原图一些标签在近黑细线中间，左右线段留出真实空白，标签本身不表示线路中断；示例与模型应把它们记录为同一逻辑边。多行标签、直连、必要圆角和外侧绕路分别可见，且需要区别真实的节点、批注与标签。
