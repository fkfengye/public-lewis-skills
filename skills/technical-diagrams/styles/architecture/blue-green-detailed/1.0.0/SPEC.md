# 蓝绿密集细节 · architecture/blue-green-detailed@1.0.0 · AR-06

本风格绑定架构语义与公共规范 `1.0.0`，同时遵守独立线条和交互规范；具体颜色和尺寸以本目录 `tokens.json` 为准。截图取色是视觉参考，不是业务颜色标准。

## 画布与层级

优先采用宽画幅、白色页面和浅青色大型系统底板。可在外层一侧设置独立外部系统区域，在主边界上部并列多个子系统，在下部设置横向跨列的资源或支撑区。排列与系统归属由业务证据决定，外部节点不能仅因靠近边框就被划入系统。

以矩形承载多级嵌套：总边界 → 子系统色块 → 功能分组 → 模块卡片 → 细项。浅蓝、蓝灰、浅绿和中蓝标题带构建视觉层次，青蓝可强调外围模块、亮绿和浅橙可强调局部卡片。配色仅辅助区分，不能从颜色推断系统部署、业务状态或资源类型。可根据内容使用横向标题带、纵向堆叠、小矩阵或窄列；同层对齐且留独立间距。正文优先横排；短标签在列窄且仍清晰时可竖排，不能用竖排掩盖文字溢出，内容过密时拆成总览和详图。

## 组件、边框与文字

背景及节点以无阴影、无渐变的直角矩形为主；外边界可用亮青细线或点线，内部卡片与嵌套分组可用深蓝细点线。标题为深色粗体，节点文字深色居中或按实际内容左对齐；同类标题和卡片保持一致字体、宽度与对齐线。浅蓝、灰蓝、浅绿、浅橙、亮青及亮绿分别以 token 明确，不将参考业务标签带入风格。

## 连线和图例

可组合深色细实线、蓝色细实线与深蓝粗点线等视觉层次。每一条关系的真实端点、箭头方向、线型和图例必须来自本次模型；原始材料未解释的线色、线型及黑色圆点不得自动推断为调用、响应或汇流。

每条有向消息只有终点箭头，请求／独立消息与响应分开布线并以实线／虚线区分；明确的共享通道连接点才可用实心圆表示。实线、点线、编号和文字应共同解释实际含义，颜色不能成为唯一线索。水平或垂直可直连时优先直连；必要时按所选独立线条样式转折，避开节点、文字和标题。无关线交叉按交互规范消歧，不把图中交叉自动变成连接。

## 示例与验收

`example.svg` 为独立构造的环境观测系统，使用不同场景和模型演示多层分区、颜色、点状边框与消息线；不得把参考材料业务、名称、原始拓扑、图片、路径或隐藏内容带入模板。可变的分区、状态和数据关系仍只由用户任务决定。

渲染全图与局部，核对所有文字真实边界、颜色对比、组归属和嵌套层次、节点碰撞、端口方向、标签和路径、响应线型、实际交点及模型语义。现有渲染脚本检查文字越界、重叠、线穿字和外链；节点相碰、端点方向、模型一致及色彩辨识仍须另行检查，不能声称已自动覆盖。
