# 浅色分层交互 · architecture/layered-interactions@1.0.0 · AR-03

本快照绑定 `types/architecture/1.0.0.md` 与 `references/common/1.0.0.md`。颜色与尺寸独立保存在 [tokens.json](tokens.json)；每次同时遵守解析出的交互规范与用户选择的线条规范，不继承其他风格的可变 token。

## 风格特征

白色画布、深蓝文字、低饱和浅蓝模块、浅青服务区、米黄数据卡片；说明用蓝灰色。外框细、留白充足，不用阴影、渐变、立体图标或侧边彩条。

系统沿主阅读方向分层，默认上下排列；外框同宽、同一左基线，常规圆角 24。内部采用等宽双列网格；同类卡片对齐、圆角 16，内容较多先扩高或换行。复杂系统可增加列或拆图，不固定系统数、节点数与层级名称。

维护真实系统归属，独立外部服务有独立边界。职责卡、内部处理动作、数据存储分别表达，不能为填满网格虚构组件或把下游服务塞进上游系统。

颜色辅助区分连接类别，不单独定义业务含义；请求与对应返回沿用相同色系，通过实线/虚线及明确标签区分。黑白打印时仍能依赖箭头、线型、编号和文字理解。

参考 viewBox 单位：主标题 38，系统标题 28，卡片标题 25–26，正文 22，线标/说明 20–21；中文默认 Microsoft YaHei / Noto Sans CJK SC / Segoe UI / sans-serif。主标题、说明、边界标题与节点分别占空间，不压缩长标识来追求固定画布。

## 连线与编号

常规节点与边界描边约 1.8，连接线约 2.1；返回虚线节奏 `7 6`。每条有向交互线只有终点箭头，请求/回调与返回/确认分别走独立端口和相邻通道。

默认线条由注册表或原图元数据决定，不由本视觉模板覆盖。正交示例优先直线与最少必要弯折；选圆角折线或直连曲线时仍保留该选择。必要的无关线路交叉用真实圆弧桥，参考半径 12；这是局部跨线，不能被误作连接点或全图圆角样式。

编号用简洁蓝色/同色系文字，不用大号彩色徽章。请求、回调、确认和查询结果分别标号；可用 `-Q/-R`、子编号和辅助前缀。逻辑顺序与真实异步到达顺序分开说明。

## 通用示例与脱敏边界

[example.svg](example.svg) 是从零设计的文件处理示例，只演示视觉与交互规则。它不是对任何具体项目节点的逐项改名，不包含真实服务名、接口、数据表、协议编号、阈值、时限或原始拓扑。

将内部图提炼为模板时，仅抽取颜色、字号、形状、间距和连接表达；示例的场景、节点、流程及数据结构须独立重建。原图、原 metadata/title/desc、隐藏文字、注释、标识、路径、哈希、链接和嵌入图片不得复制进技能、预览或模板历史。无需为了说明风格而保留来源文件名或公司信息。

## 验收

- 检查系统框同宽、节点网格对齐、层级清楚；配色和字体层级符合本快照。
- 每条有向线只有终点箭头，独立虚线返回与回调语义清楚，交点过桥且不穿字穿框。
- 逐项核对模型和编号，模板不能替代本次任务的业务事实或强加示例的实体数。
- 扫描交付文件的全部 XML 文本、属性、注释、metadata 以及预览生成内容，确认无来源业务残留、外链或内嵌原图。
