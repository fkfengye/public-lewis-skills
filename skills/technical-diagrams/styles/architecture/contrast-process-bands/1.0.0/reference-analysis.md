## 画布、整体阅读路径

- 原图为 3200 × 2780 横向画布，宽高约 1.15:1。页面为近暖白色底，左上是占比较大的黑绿色粗体标题，右上横排四项带线样的图例。标题、图例、内容区之间留有明显空白。
- 主体采用「顶部横条 + 中央纵向堆叠分区 + 右侧窄栏」：事件入口横跨顶部；下面从上到下为深绿中台、暖米执行、浅青 CI、暖白橙框判断四块；数据沉淀位于右侧，横向跨越中台至判断区。每块先容纳自己的节点，再让连线跨分区流动。
- 右侧窄栏约占内容总宽的 15%，左侧主区约占 82%，其间留出线条通过的沟通槽；主区内边距、四个分区的左右边界和多数节点的水平基线相互对齐。深绿区、执行区、CI 区、判断区高度随内容变化，并非等高泳道。
- 标题位置有意变化：事件和 CI 标题靠左，深绿中台、执行及判断标题靠右，数据栏标题靠左。视觉上有层次，但标题位置不表达标准化的权责语义。

## 分层、容器与组合

1. **事件层**：浅蓝灰底、蓝色细描边的长圆角容器；左侧是「事件」标题，后面横排六个等高白色或浅色圆角卡片。一般来源用白底浅灰边，新来源使用更细的点线边；「决定」采用浅橙底、橙边和橙字。多数卡片大小一致，间距规律。
2. **中台层**：深绿色大圆角底板，右上黄字标题；内部「鉴权 → 去重 → 匹配规则 → 排队 → 派单」横向排列，节点为灰绿底、淡灰绿边、浅色粗体字。节点与底板均为圆角矩形，箭头和标题因深底改用浅色。
3. **执行层**：暖米色底、棕色细边的大圆角容器，标题靠右上。上方一整条紫色描边的 Skill 标签组，内部七个小白底紫边标签横排；下方左边是接单程序与三个纵向堆叠的执行器选项，右边是读取、核实、判断、处理和提交的一条主链。执行器有橙色、蓝紫色实边及蓝紫色虚边等区别；图中相关图标是该样例的内容，不是本风格的必备图元。
4. **CI 层**：浅青底、青绿色边框、左上青绿色标题。执行层中「开 PR」向下连接交付程序，CI 主链从右往左依次穿过审查、判断、完整检查、判断、合并、发布、线上核实；判断菱形与处理矩形混排，回退线向上回到执行层。
5. **判断层**：暖白底、橙色边、右上棕橙色标题。结果回执横向连接两个判断；一条分支向下到重派，另一条到结案；需要人工决定时经过浅蓝框、内含两个白色子卡片的消息区域，再到浅橙色人物决策框。
6. **数据沉淀侧栏**：浅灰底、灰蓝边，内部多枚白底灰蓝边的圆柱排列，分别标示事件、运行、会话、审查、CI 和决定记录；侧栏底部有深灰蓝色圆角行动块。顶部与底部间有较大留白，按记录对应的主区高度对齐，不强行等距填满。

## 图元、字体与细节

- 以圆角矩形为主要容器和操作节点：分区圆角较大，卡片圆角较小；分区边框约 1–2 逻辑像素量级，线条和字重比边框更醒目。大区不加渐变和投影；图中以平面色块为主。
- 判断使用白底菱形，主判断为深灰绿色边；人工介入判断改用橙边。必要条件文字放在线路旁或菱形出口附近，不能仅靠位置表达真假。
- 记录使用标准圆柱体外形：上椭圆、中间白色主体和下部弧线，轮廓颜色与侧栏标题一致；容器表示记录集合，不自动推断数据库种类或部署方式。
- Skill 层将一个紫色组框与多个圆角小标签组合；消息层用一个浅蓝外框包裹两个白色子卡片；决策人物单独占一个浅橙大卡。组框代表图中显式的包含，不可仅凭重叠判断归属。
- 主标题最大，分区标题次之，常规节点和图例再次之，分支条件、箭头旁标注较小；节点文字多为居中粗体中文，标题和图例水平排列。不同字号应随最终导出尺寸适配，文字不能被线条或边界遮挡。

## 线条、箭头与标签

- 顶部图例明确区分四种含义：深灰绿实线为主流程，蓝紫实线为退回／重派，棕橙实线为人的决定，灰蓝虚线为写入记录。它们只说明此原图；新图含义由业务模型和图例决定。
- 主链大多使用水平或垂直直线，跨层和回路使用正交折线，较长折线的转角带圆角。深绿背景内的主箭头及文字变成浅色，跨出深色区域后切回深色以保持对比。虚线记录线从主区指向侧栏记录；回退线和人工决定线分别以紫色、橙色突出。
- 箭头多数为单向实心三角；线条连接节点边缘，判断分支在出口附近标「是」「否」「要」「不用」等。部分线条从下方跨越多个分区或绕画布边缘返回，沿外侧留出独立通道，不穿越文字；这些回路只在实际关系存在时绘制。
- 原图中执行层的返回修改线、判断层的重派线以及右侧人工决定回流体现不同回路；线条在屏幕上的接近或交叉不等于存在逻辑汇合。图示中的上下／左右方向是原图布局，不能仅凭空间方向推断同步、异步或调用先后。
- 原图没有把独立响应逐条展开；复用风格画新图时，仍按技能交互规范处理请求、确认和返回，依据实际关系标示箭头、虚实线及编号。原图线条的形状不覆盖本次用户选择的直角折线、圆角折线或直连曲线。

## 实用验收

1. 按实际职责建立内外边界和分组，核对每个节点归属；大区同边对齐，留足标题和侧栏空间，分区数量随业务改变。
2. 核对底色、节点、标题、描边、虚实线和箭头在深浅底上的可读性；用图例或文本解释全部线型和颜色，兼顾灰度阅读。
3. 核查每个节点和圆柱轮廓内的文字、标签间距、转角、端点方向、交叉、回路和分支标注；直线可达时不增加多余折点。
4. 缩略图与大图都查看：缩小时检查标题层次、分区轮廓和主要路径，大图检查密集标签及穿线。原图作为参考查看，不将其中业务结构默认套进无关新图。
