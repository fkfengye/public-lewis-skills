# AR-08「跨域分层交互」原图分析

本文分析用户授权保存的[原始参考图](../../../../assets/reference-examples/ar-08-original.png)，供对照画布分区、节点、线条和编号。原图中的机构、支付业务和品牌仅为图中内容；新图的系统归属、业务关系及语义以用户资料为准，不默认复制。下列色值是参考像素，生成时以风格 token 为准。

风格目录中的四层通用示例是简化场景；要检查原图更完整的五层构图、节点组合和线型，可查看[特征展示图](feature-atlas.svg)。该图使用独立内容展示可选视觉元素，不代表新增固定业务模板。
### 画布、方向与总体层级

- 图片为 1982 × 1076 横向宽画幅，约 1.84:1；白色背景、黑色文字、蓝色线条为主。没有总标题，内容几乎铺满画布；左侧用淡蓝竖向标签标识层级，标签文字逐字竖排。
- 从上到下依次为「最终清算层」「清算网络层」「代理结算层」「支付处理层」「交易层」五个水平层次，层高按内容和跨层线条调整，并非固定等高泳道。
- 画面中央有一条贯穿多层的蓝色竖线，上方分别标「境内」「境外」，提供左右域边界；多条线跨越该边界，图中还有居中跨域设施。边界仅表示原图标明的分区，不等同于流程阶段或所有节点的系统归属。
- 上、中、下各层在左右两边大致对应，但并非镜像复制：左边的节点数量、跨域通道及右边的多币种账户、支付工具和商户各不相同。必须依真实内容建模，不能为了对称补充节点。

### 分层结构与组件组合

1. **最终清算层**：左右各一条浅绿色长条底板，细淡蓝边框；每条上方有淡蓝标题带，底板内有三个浅绿色、蓝色细描边的横向椭圆节点。左右各自以蓝色水平箭头串联；中央靠上单独放淡蓝矩形，连接左右跨域链路。
2. **清算网络层**：一个几乎横贯全宽的蓝色矩形外框，内部并列左侧本地网络、中央跨域网络、右侧本地网络；子区以蓝色虚线矩形分隔，标题叠放在上边界处。左、右区域含灰底蓝边的窄矩形系统标签；中央和左右局部包含原图中的品牌标志或图标。标志属于参考图内容，不是通用风格必需图元。
3. **代理结算层**：五个横排但宽度和位置不完全相同的浅橙色矩形组，配淡蓝标题带；组内各有一个浅绿色椭圆账户节点。该层与上方网络、下方处理机构通过垂直箭头相连，部分线条跨越边框。
4. **支付处理层**：左侧和右侧各一个浅灰色大矩形组、淡蓝标题带；左组内部包含多个蓝色虚线椭圆并以水平箭头连接，右组包含浅绿横条及一排纵向窄小的蓝色虚线圆角账户。组之间、组外侧有蓝色点线与黑色虚线连接。
5. **交易层**：左侧消费者图标、右侧商户图标，中间偏右为带标题带的支付工具/方式容器，内部再以点线矩形组合若干图标及文字；一条蓝色粗点线从左到右跨过底部，连接工具区与商户。图标和原图文字只是该示例的业务内容，不自动迁移到新图。

### 颜色、形状、字体与尺寸层次

| 角色 | 近似颜色 | 原图用途 |

| 页面 | `#FFFFFF` | 白色背景 |

| 账户／清算底板 | `#DFF3D7` | 顶层底板、椭圆节点及部分信息条 |

色值为采样近似，可能有抗锯齿偏差；新增风格需定义自有 token。多用直角矩形和浅色填充，账户使用扁长椭圆；标题带通常与组边缘重叠，层标签为窄竖条。各层和组件边框、虚实线、填色存在组合变化，颜色本身不自动定义状态、领域或系统部署方式。

文字以中文黑色无衬线为主：组件名称居中，步骤注释比节点名称小；组标题在淡蓝标题带上居中。竖排仅用于左侧较短层名和少数窄账户标签；通用场景优先横排并以内容决定宽高，避免竖排导致难读或溢出。

### 线条、箭头、编号与不确定项

- 原图包含蓝色实线箭头、细蓝虚线箭头、蓝色粗点线箭头和黑色虚线箭头；同时有蓝色实线系统边界、蓝色虚线分区边界及中央实线分界。边框与连接应按角色区分，不能仅凭颜色或虚实线推断含义。
- 顶层主要是水平箭头；中间多为上下跨层的直线，局部跨域连接采用斜向虚线；底部主路径采用长距离蓝色粗点线和必要折线。线条旁有编号与说明，如支付请求、购汇、结汇等，节点端点及箭头方向需要逐条核查。
- 原图没有单独解释所有线型的图例，蓝色虚线、蓝色粗点线、黑色虚线不应自动映射为某种通用消息语义。新图应按真实模型分别记录关系、方向、条件、线型和图例，并遵守现有请求、响应及确认规范。
- 原图的步骤标号并非可直接假设为唯一顺序：例如画面中「6」和「9」分别出现多次，另有无编号的连接说明。若按原业务复刻，应原样保留并提示待确认；新增通用示例应依据自己的模型明确编号，不能擅自修正原图或声称该图已给出完整无歧义顺序。
- 不应把跨线、重叠、分界线上经过或图标与边框的接近推断为连接；仅凭截图不能确定系统协议、机构边界、实时性和数据流含义。
