# 跨域分层交互 · architecture/cross-boundary-layers@1.0.0 · AR-08

本风格绑定架构语义与公共规范 `1.0.0`；颜色和基础尺寸使用本目录的 `tokens.json`。独立线条和交互规范定义实际连线几何、请求／响应、箭头、编号及系统边界，业务模型以本次用户资料为准。

## 分层与跨域布局

使用白色宽画布，按真实职责从上到下排列横向层级；可在左边采用淡蓝窄标签带标注短层名。按真实边界将内容划分为左右或多个区域，可使用独立的蓝色分界线及文字；跨域节点、外部系统与共享通道依据实际模型单独标明，不能凭位置推测归属。层数、左右域数、组件数量和具体方向均由任务决定，不要求对称或固定五层。

层内使用浅绿横向区域、浅橙子组或浅灰处理区，在组边缘可使用淡蓝标题带。必要时用蓝色矩形总框和虚线子框表达网络与分组；边框是结构而不是消息。账户或其他语义适合的状态节点可使用浅绿填充的横向椭圆，处理节点及说明用矩形或白色标签；形状应与业务实际相符，不得强制把所有系统画成账户。

## 组件、颜色与文字

蓝色细描边配浅绿、淡蓝、浅橙和灰色平面填充；背景为白色，节点文字深色居中，标题带和线条标签保持清晰留白。短层名可竖排，长名称优先横排、扩容或拆图，避免缩小到不可读。区域、容器和节点的组合关系必须有来源依据；不把颜色或线型单独解释为系统类型、部署、资金或执行状态。

图例、箭头标签和编号遵循真实模型，图标与品牌只在用户明确提供并需要时使用；不要复制参考材料中的具体机构、名称、交易流程或标志作为通用模板。

## 连接、编号与验收

按实际源、目标和语义为每条有向消息分别选择端口与终点箭头；请求与独立消息用实线，返回／确认用独立虚线，具体以独立交互规范和模型为准。蓝色实线、蓝色虚线或粗点线、黑色线条可用于视觉区分，但必须有图例或文字，不可仅凭线型推断其业务含义。原图存在重复步骤号和未定义线型，复刻时保留并提示待确认，不能擅自改写。

跨层共线优先直连，只有避障需要才根据用户选择的直角、圆角或曲线样式转折。区分域边界、分组边框与连接；线条经过边界或彼此交叉不自动成为汇合。为逻辑请求、响应、分支及确认标明独立且可追踪的编号，异步顺序不承诺全局到达先后。

`example.svg` 为独立的物资协作场景，展示两域、四个职责层和清晰编号的单向交互；其名称、关系与节点数不作为默认业务。用户授权的原始样例由风格目录单独提供。

验收全图和局部：检查域／层归属、边界、真实节点、文字、标签、连接方向与实际编号；渲染检查文字越界、重叠和线穿字，并另行人工核对节点碰撞、端点与业务语义。
