# 多域 DDL 表结构 · er/domain-ddl@1.0.0 · ER-03

本快照绑定 `types/er/1.0.0.md` 与 `references/common/1.0.0.md`。只读取本目录 [tokens.json](tokens.json)，不继承 `er/soft-tables` 或其他风格的 token；ER-01 与 ER-02 的编号、profile 和固定示例保持不变。

适用场景：实体较多、需要同时表达逻辑引用与物理约束的复杂 ER 模型。用业务域分区组织表卡，表内采用「键 / 字段 / 类型·可空」三列 DDL 详细视图，并配套图例、约束说明与范围声明。只需两三张表的逻辑总览时改用 ER-01。参考图来自本技能已有风格的一次复杂复绘，[原图分析](reference-analysis.md)记录观察与推断的边界；原图业务数据不进入通用示例。

## 画布与分区

白底宽幅长图，长边由内容决定，不为迁就屏幕缩小字号。左上为主标题（36）与副标题（20），右上两行元信息（19 / 18）写明固定编号与 profile、模型层级和箭头含义；底部用一条细分隔线带出「约束与实现边界」与范围声明。

业务域用虚线圆角框分组：圆角 20、浅蓝灰底、边框虚线 `10 7`、线宽 1.6；域标题 22 粗体并带 `01 / 02 / 03` 序号，只表示阅读分组，不代表部署边界或层级调用。域数按实际模型决定，不固定为三个；域框可不等宽，域内表卡按归属错落排布，跨域关系走域间空白通道。**域内行序优先按引用链重排**，让被引用表与引用它的表尽量同层，减少跨行绕行；重排不改变域归属、字段或业务语义。

## 表卡四段式

每张表是圆角白底卡（圆角 16、边框 1.8），自上而下固定四段：

1. **浅米黄上圆角表头（88）**：中文表名 26 粗体、物理表名 18、右侧单字母实体徽标 24 蓝色粗体。徽标只用于线旁标签指代实体，不是键、不是基数。
2. **列标题带（36）**：浅蓝灰底，`键 / 字段 / 类型 / 可空` 三列，17 粗体。
3. **字段行（每行 44）**：键标记 17 粗体橙棕（`PK` / `UK` / `UK*` / `FK X` / `FK/UK`）、字段名 20 深蓝、类型与可空 18 灰蓝右对齐；`?` 表示可空。行间用 1.1 细线分隔，长标识按真实字体度量扩宽表卡，不压缩进相邻列。
4. **表尾旁注带（46）**：16 灰蓝，用一句话写业务约束（如「停用不删历史引用」「UK(team_id, user_id) 消解 M:N」）。旁注卡不是关系端点，关系线不得终止于旁注。

与 ER-01 的区别：本风格是**高密度 DDL 详细视图**（字段行 44、字号 20/18/17/16/15），ER-01 是低密度逻辑总览（字段行 ≥72、字号 24/22/28）。两套数值各自冻结，不互相覆盖。

## 关系与标注

引用线用灰蓝实线（1.8）圆角正交折线，转角用真实 `Q` 圆弧（半径 16，短段按可用长度收缩），从 FK 字段行引出，端点落在被引用表的**对应字段行**；端点为 11×12 实心三角，**方向为「引用字段 → 被引用字段」**，不表示基数、执行顺序或约束强度。**入线侧按来源域决定**：源在目标右侧时从目标右边缘进入，源在左侧时从左边缘进入，同域关系走靠内的空隙侧；指向同一字段的多条引用因此分散到目标表两侧，不得把所有箭头堆在同一边缘。同色同线型不区分逻辑引用与物理 FK：类别以键标记和线旁标签为准，物理 FK 必须有 DDL/迁移证据，不凭线型猜。

线旁标签**同时写关系名与基数比例**，按布线方式选排版：长垂直通道用逐字竖排关系名（14 灰蓝）+ 橙棕小字（12）三段竖排比例（左基数 / `:` / 右基数，`0..*` 整体横排不拆点号）；近水平直连的短折线用单行横排「关系名 `1:0..*`」（15 粗体深蓝），并动态寻找与所有水平段都不相交的位置，**不得靠白色遮罩压线**。每条关系线都必须在线旁给出基数，不得只把基数集中放进图例或注记卡。比例按「引用端可见目标数 : 目标端可见引用数」记录，说明卡可用带空格的 `0..1 : 0..*` 对照；`0..1 / 1 / 0..* / 1..*` 只能依据明确来源，或由有证据的 FK、目标唯一性与引用列可空性推导，未知时写「基数待确认」。标签保持单列宽度，相邻通道的标签不会横向相撞。标题下方必须声明本图是逻辑/物理混合模型以及箭头含义；图例不可省略，须解释 `PK / FK / UK / UK* / FK/UK`、`?` 与 `FK` 后的字母徽标。

### 布局与端口分离

- **先调排版再布线**：域内行序按引用链重排，让 FK 字段行与被引用 `id` 行尽量同层；纵向差 ≤ 88 的关系在目标表外侧 40 处短折、近似水平直连，不占用长垂直通道；只有差更大时才分配长通道，通道 x 间距 ≥ 70，竖排标签互不侵占。
- **端口不越行**：同一字段行被多条引用时，同侧端口在该行内 ±14 分布（间距 28，箭头高 12），所有端点仍归属该字段行，不得滑到相邻字段造成误读；按来源域分侧后同侧通常不超过 2 条。
- **标签避让实线**：横排标签逐条检查全部水平段并选不相交的 y；白色文字描边只可用于标签自身可读性，不得用来掩盖穿字或代替布线调整。
- **记录取舍**：`overrides.connectors.routing` 记录直连 / 通道条数、通道 x、端口间距、标签策略、桥数与取舍依据，模型弯折数须与 SVG 路径一致。

## 说明体系

- **键与可空速查**：白底图例卡，逐条解释键标记、可空符号、复合唯一与 FK 字母。
- **角色外键索引**：列出同一实体被多处引用的字段及必填/可空，说明引用位置，不新增关系。
- **约束与实现边界**：底部横向四组（数量按内容决定），用小标题 + 要点写当前与历史、幂等与顺序、删除与可空、唯一与时间等实现约束；这些是业务旁注，不画成实体或关系。
- **范围声明**：页脚写明模型边界与未展开内容；看不清或资料不足的字段标为待确认，不补造。

说明卡与表卡用底色和边框区分，均不接关系线。所有连线标注 `data-diagram-role="connector"` 便于几何检查。

## 语义与验收

字段集合、类型、可空性、键、引用方向、条件与基数以 `type_spec_path` 和来源 DDL 为准；视觉样式不得改变其中任何一项。通用 [example.svg](example.svg) 使用独立的「在线课程平台」模型，不复用原图的表结构、字段或业务约束；验收逐项核对三域归属、四段式表卡、键标记、旁注、图例、约束卡、圆角折线端点、箭头方向与基数证据，逐条核对线旁标签都含关系名与基数比例，并按最小弯折 → 最短路径 → 最少交叉的量化顺序核对走线；核对指向同一字段的箭头已分侧且同侧间距 ≥ 28、长通道间距 ≥ 70、剩余交叉逐处圆弧桥，同时检查文字真实边界、节点净间距、标签不压线和线路是否穿字。
