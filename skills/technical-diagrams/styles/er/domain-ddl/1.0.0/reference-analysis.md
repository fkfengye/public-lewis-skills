# ER-03 多域 DDL 表结构：参考图分析

来源文件：`outputs/ticket-er.svg`（分析时位于项目根 `outputs/`），3020×2420、单行 SVG、白底不透明。它是本技能 `er/soft-tables@1.0.0`（ER-01）的一次复杂复绘，图中右上角自标注 `ER-01 · er/soft-tables@1.0.0`。用户已明确授权把该原图保存进技能，并由风格目录的「查看原始样例图」单独打开；原文件会随技能目录与生成的预览一起分发。

本文区分三类信息：**直接观察**（SVG 几何与文本）、**图内文字给出的明确语义**（图例、标题、范围声明）、**推断**（需用户确认才能固化为规则）。原图中的「企业工单系统」表结构、字段、约束和范围声明都是示例业务内容，不是可复用的视觉规则，也未进入通用示例。

## 1. 画布与阅读结构

- 白底 3020×2420，横向宽幅（约 1.25:1），390 段文本、12 张实体表卡，信息密度高但长边由内容决定，未为迁就屏幕缩小字号。
- 左上：主标题 36 深蓝粗体「企业工单系统 ER 模型」，下方 20 灰蓝副标题说明实体数、三域和箭头含义。右上：两行右对齐元信息（19 / 18），写明固定编号与 profile、模型层级与箭头含义。
- 底部：一条 1.6 细分隔线（y=2210，x 80→2900）带出「约束与实现边界」四组横向要点，最下方一行范围声明。
- 阅读方向：由左至右三个业务域，域内自上而下；无图例重叠、无跨页裁切。

## 2. 排版与层级

- 三个虚线圆角域框（`rx=20`、填充 `#F7FAFC`、边框 `#D5E2EC` 虚线 `10 7`、线宽 1.6）：01 组织与人员（980×1096）、02 工单业务（1400×1948）、03 服务保障（540×1296）。不等宽，域标题 22 深蓝粗体，编号只表示阅读分组。
- 域内表卡按归属错落排布（左域 2×2、中域多列多行、右域纵向），表卡宽度按最长字段自适应：370 / 380 / 420 / 470 / 480 / 560 六档；同类表卡圆角、边框、四段结构完全一致。
- 表间留出 40–60 的走线槽，跨域关系走域框之间的空白通道；说明卡放在域框下方与页脚上方，不占据表卡网格。

## 6. 线条与箭头

- 12 条引用线同为 `#8096A6` 实线 1.8，正交折线并带真实 `Q` 圆弧转角（半径 16），从 FK 字段行所在高度的表卡边缘出发，经表间或域间外侧通道，到达被引用表对应字段行的边缘。
- 箭头为 11×12 实心三角，方向为「引用字段 → 被引用字段」。图内文字明确声明「箭头表示引用方向，不代表基数」，因此**不把箭头当作双向消息、执行顺序或约束强度**。
- 所有线同色同线型，逻辑引用与物理 FK 不用线型区分；类别以键标记（`FK X`）和线旁标签为准。这与 `types/er/1.0.0.md` 中「物理 FK 必须有 DDL/迁移证据」一致，不能凭线型补造外键。
- 部分关系标签竖排贴线（如「派单记录 1 : 0..*」），另有横排基数注记（如「当前处理组（可空）0..1」）分布在表间空白。行分隔线属于网格，不是关系连接。

## 7. 语义与标注（图种特有）

- 12 个实体各有单字母徽标 D / U / G / M / C / T / E / N / A / F / S / L，供 `FK X` 与线旁标签指代被引用实体；徽标不是键、不是基数。
- 键标记体系：`PK`、`UK`、`UK*`（复合唯一的一部分）、`FK X`、`FK/UK`（既是外键又带唯一约束，见 `ticket_sla.ticket_id`）。图例逐条解释，并说明「`?` 表可空、FK 后字母为引用实体」。
- 表尾旁注写业务约束，例如「组织单位 / 停用不删历史引用」「UK(team_id, user_id) 消解 M:N」「聚合根 / version 乐观锁」。
- 说明体系：左侧「角色外键索引：用户被引用的位置」列出 6 处 `user_id` 引用及必填/可空；「键与可空速查」图例；底部「约束与实现边界」四小节（当前与历史 / 幂等与顺序 / 删除与可空 / 唯一与时间）；页脚声明「单中心单租户；RBAC、通知、多租户未展开」，并注明「看不清的字段记为待确认，未自行补造」。
- 副标题与图例都写明「基数依据各表 UK 与可空性推导」，符合语义契约中「基数只能由明确来源或证据推导」的要求；没有鸟爪符号，没有未解释的线型。

## 9. 待确认与边界

- 原图线旁出现的 `1 : 0..*`、`0..1`、`1 : 1..*` 等基数标注，图内文字称「依据各表 UK 与可空性推导」，但未提供 DDL 或迁移脚本作为证据。本风格沿用「线旁标注基数比例」这一形式（见 `SPEC.md` 与 `types/er/1.0.0.md`），但**不沿用原图的具体数值**；新图仍须逐条记录证据，未知写「基数待确认」。
- 原图所有实体均为单字母徽标，无法确认这是否为该业务模型的特有约定；SPEC 只把徽标定义为「线旁标签指代实体」的可选手段，不规定每个模型必须启用。
- 域框数量 3、实体数 12、字段行数均为原图业务规模，不作为新图的固定数量。
- 原图是技能自身产物而非外部素材，无水印、品牌标识、外链或嵌入脚本；授权保存的原图以 PNG 形式单独展示，通用示例与预览不复制其业务数据。
- 渲染核验：Chrome 无头渲染全图、上半通道区、课时 / 班级箭头密集区与说明卡区，确认表卡内文字无压线、节点不碰撞、端点方向可辨、同字段箭头分侧且落在同一行内、横排标签不压线、3 处圆弧桥与跨线图例、图例与页脚完整；该检查不能证明业务语义或 FK 证据，语义另行按模型核对。
