# 独立线条样式规范 v1

规范版本：`1.0.0`。本规范只约束连线几何，与图种语义、视觉 profile 分别选择；不改变节点、配色、字号、箭头和虚实线语义。独立线条选择覆盖旧公共或视觉规范中一般性的正交、圆角偏好，图种语义约束仍优先。

## 1. 注册与选择

可用 ID、中文名称与别名以 `registry/shared/line-styles.json` 为准，由 `catalog.py` 汇总为 `line_styles`。

| canonical ID | 名称 | 几何规则 |
| --- | --- | --- |
| `orthogonal` | 直角折线 | 默认。共线无障碍时直连；必要转折使用水平/垂直直角折线。 |
| `rounded-orthogonal` | 圆角折线 | 保留直连优先；必要转折使用真实曲线圆角，常规半径 `18`。 |
| `curved` | 直连曲线 | 共线无障碍时仍直连；非共线端口优先用单条平滑三次贝塞尔曲线。 |

三者均使用版本 `1.0.0`；没有选择时使用 `orthogonal`。线条 ID 不占用 FC/SQ/ST/AR/ER 固定编号，不复制视觉风格目录。

选择顺序：本次用户明确指定 > 当前 `.diagram.json` 的 `line_style` > 可识别的旧 `overrides.connectors` > 注册表默认值。后两种元数据来源共同属于“沿用原图”。同一图种的视觉样式可以通过完整名称、ID、别名、固定编号或完整 key 选择，线条选择独立应用。

旧覆盖项只在明确表达直角、圆角折线或直连曲线时归一化；保留其中有效的具体参数。不能仅凭 `radius` 或 `stroke-linejoin="round"` 推断全图采用圆角折线。未知的本次输入、未知版本或损坏的新 `line_style` 元数据须报错并列出可选项；没有可识别旧选择时采用默认值并记录来源，不猜测旧曲线路径的含义。

## 2. 调用与解析结果

以下命令从技能目录之外的工作目录运行，`<技能目录>` 指本技能所在目录。技能移动或安装到其他位置时只需替换该路径，工作目录与产物目录仍在技能目录之外。

```text
python -B <技能目录>/scripts/catalog.py list --line-styles
python -B <技能目录>/scripts/catalog.py resolve --number FC-01 --line-style rounded-orthogonal
python -B <技能目录>/scripts/catalog.py resolve --type flowchart --style 浅色业务流程 --line-style 圆角折线
python -B <技能目录>/scripts/catalog.py resolve --style flowchart/soft-process@1.0.0 --line-style curved
```

`list --line-styles` 查看线条注册；普通 `list` 保持原有视觉 profile 数组格式。`resolve` 在原有 profile 字段之外返回：

| 字段 | 示例 | 用途 |
| --- | --- | --- |
| `line_style` | `rounded-orthogonal` | 归一化的独立线条 ID |
| `line_style_version` | `1.0.0` | 线条规范版本 |
| `line_spec_path` | 解析后的 `references/line-styles-v1.md` 路径 | 本次必须读取的规范 |

结果同时提供线条规范的依赖摘要。编号、图种默认风格和完整 key 三个入口都必须保留传入的线条选择；不得因编号绑定视觉 profile 而丢弃线条参数。未知线条报错，不静默回退。CLI 不代替代理读取 `.diagram.json`；复绘时先按优先级确定线条，再将其传给 `resolve`。

自然语言示例：

```text
使用 technical-diagrams 绘制流程图，样式 FC-01，线条样式圆角折线。
使用 technical-diagrams 绘制流程图，样式浅色业务流程，线条样式直连曲线。
将现有图改为 ER-01，未指定线条时沿用原图元数据，保留字段连接与基数标记。
```

## 3. 通用布线规则

1. 先确定真实端口和箭头方向，再选择通道。端口共线且没有节点、标签、端口或分组边界障碍时直接连接，不为展示线条样式增加绕行。
2. 只有存在实际避障或语义约束时增加转折、通道或控制点。使用最少的必要转折，并给节点文字和边标签留出空间。
3. 线条端点落在规定端口或节点边界，不能侵入文字。曲线路径、圆角及箭头末端均要检查，不能只检查控制点或包围盒。
4. 标签与线条分配独立空间；变更几何后重新检查标签。文字背后铺白色遮罩不能代替合理布线。含基数语义的关系线，标签必须在**线条旁**同时给出关系名与基数比例（如 `1 : 0..*`），不得只把基数集中放到图例或注记卡；未知基数写「基数待确认」，不猜一对多。
5. 同一关系的箭头、虚实线、同步/异步标记和基数符号沿用图种语义与视觉 profile。不得把交叉误画为汇流，也不得把实际连接点画成断口。

### 3.1 量化布线指标与取舍顺序

布线质量用三个可比较的指标衡量，取值以 SVG viewBox 坐标为准：

| 指标 | 记号 | 定义 |
| --- | --- | --- |
| 弯折数 | `B` | 单条路径中方向改变的次数。直连为 `0`；直角折线每次 `H↔V` 计 1；圆角折线按等效正交通道的转角计数（真实 `Q`/`A` 不额外计数）；曲线按必要的非共线转向计 1，不能靠增加控制点伪造更少弯折。 |
| 路径长度 | `L` | 路径几何总长：折线为各段长度绝对值之和；曲线用沿路径采样折线近似。只用于同一模型、同一端口集合下的方案间相对比较，不跨图比较绝对值。 |
| 交叉数 | `C` | 全图中**无关连接线之间**的实际交点总数。真实 T 形汇流、共享干线连续接点、共用端口与同一路径自交不计；由圆弧桥覆盖的交点仍计 1。 |

**硬约束先行**：图种语义、系统归属、端口与箭头方向、不穿节点/文字/分组标题、箭头与标签的安全留白、真实汇流连续，均不可为降低指标让步。硬约束成立后再按以下字典序取优：

1. **最小弯折数 `B`** —— 逐边枚举可行端口、邻接位置与 ER 字段展示行，取 `B` 最小的方案；共线直连天然 `B=0` 且长度最短，优先采用。
2. **最短路径 `L`** —— `B` 相同时取 `L` 最小；不为省一点长度制造 U 形长绕路或把节点贴紧。
3. **最少交叉数 `C`** —— `B` 与 `L` 仍相同时，取使全图 `C` 最小的方案。

字典序意味着：**减少交叉不得以增加弯折或路径长度为代价**；反之，为降低 `B`/`L` 而保留的交叉是允许的，但必须按 §3.2 全部用圆弧桥处理。禁止用「已加跨线桥」跳过前两项比较，也禁止把桥当作保留可避免绕行的理由。

每条边记录已比较的可行方案及其 `B / L / C` 结果；采用非直连方案时记录取舍依据（写入 `overrides.connectors` 的布线记录或复绘报告）。模型中的弯折数须与 SVG 路径一致，不得出现「模型写直连、SVG 画折线」。

### 3.2 剩余交叉一律圆弧桥处理

按字典序比较后仍存在的无关线路交叉，**每一处**都必须用真实 `A`/`Q` 圆弧桥处理，并在图例说明「跨线不连接」。本规范只约束「何时必须有桥」：不得以已加桥跳过 `B`/`L` 比较，不得因 `C` 优先级最低就省略圆弧处理，消除交叉后须同步删除多余桥弧、衬线与已不适用的跨线图例。桥的半径、收缩、白色衬线、汇流连续性与全交点验收细则见 `interaction_spec_path`；跨线桥是局部消歧手段，不改变所选 `line_style`。

## 4. 几何要求

### 4.1 直角折线 `orthogonal`

共线直连示例：`M160 160 H360`。必要的非共线路由可以用 `M160 160 H240 V240 H360`。所有转折为水平/垂直直角，箭头方向与末段切线一致。不要把两点间可用的直线替换成 U 形绕行。

### 4.2 圆角折线 `rounded-orthogonal`

先确定正交通道，再将必要的外侧转角改为实际 `Q` 或 `A` 路径。常规半径 `r = 18`，单位沿用 SVG 的 viewBox 坐标。对短段收缩为 `r = min(18, 入段可用长度 / 2, 出段可用长度 / 2)`；相邻圆角的切点不得交叉。退化短段先合并冗余点，再计算半径。

两次转角的真实二次贝塞尔圆角示例：

```svg
<path d="M160 160 H222 Q240 160 240 178 V222 Q240 240 258 240 H360"
      fill="none" stroke="currentColor" />
```

`stroke-linejoin="round"` 只改变描边连接外观，不能替代路径圆角。直连边仍是直线，无需人为加入曲线。外侧汇流通道的拐角也遵守同一半径规则；内部 T 形接点保留共享干线和精确接触的分支，接点不能用修剪圆角制造空隙。多条路径共用端点时检查像素级连续性及箭头叠加。

### 4.3 直连曲线 `curved`

端口共线且无障碍时仍用直线。非共线时优先使用单条平滑 `C` 路径，按端口的出入方向放置控制点。例如左右端口可用：

```svg
<path d="M160 160 C240 160 280 240 360 240"
      fill="none" stroke="currentColor" />
```

起终点切线须匹配端口方向，避免刚出节点便回折、尖点或无意义波浪。遇到障碍先调整控制点或通道，确需多段曲线时保持连接处切线连续。箭头与 ER 标记按终点切线对齐。不要仅将原折线的每个折角稍作圆滑就称为直连曲线。

## 5. 图种限制

| 图种 | 线条可调整部分 | 必须保留的语义 |
| --- | --- | --- |
| 流程图 | 流转、分支、汇流与必要回路 | 条件归属、方向、节点集合；实际汇流点连续 |
| 时序图 | 自调用、必要绕行或辅助连接 | 普通消息保持水平，时间自上而下；同步/异步、返回虚线、激活与片段边界不变 |
| 状态图 | 迁移、自循环与回路 | 初终态、方向、事件/条件/动作及状态集合不变 |
| 架构图 | 组件连接与跨组通道 | 层级、分组边界、依赖方向、协议与连接含义不变 |
| ER 图 | 字段端口之间的关系路径 | 保留真实字段端口、逻辑引用/物理 FK 区别、引用方向、可选性与基数标记；不给来源未声明的关系补约束 |

时序图的“直连曲线”不将普通消息改成斜线或弧线。ER 图不能因避障把 FK 端点移到实体标题；需要增加端口附近短直段来容纳基数标记时可以保留短直段，并使其与主体曲线连续。

## 6. 元数据与稳定复绘

`.diagram.json` 保留原有 profile、模型、依赖字段，新增独立线条对象；几何细节放在已有 `overrides.connectors`。下例仅展示相关片段，摘要须填实际 SHA256：

```json
{
  "profile": "flowchart/soft-process@1.0.0",
  "line_style": {
    "id": "rounded-orthogonal",
    "version": "1.0.0",
    "source": "explicit"
  },
  "overrides": {
    "connectors": {
      "corner_radius": 18,
      "short_segment_radius": "shrink-to-fit"
    }
  },
  "dependencies": {
    "references/line-styles-v1.md": "<该文件的实际SHA256>"
  }
}
```

`line_style.source` 表示本次选取来源：`explicit` 为本次明确指定，`metadata` 为沿用已有独立对象，`legacy-overrides` 为识别旧覆盖项，`default` 为固定默认值。写入时始终保存 canonical ID 和确定版本，不把中文别名作为稳定标识。

`overrides.connectors` 只记录本图实际采用的几何细节，例如圆角半径、短段收缩或特定绕行；不将连线颜色、业务关系或视觉 profile 复制成第二套注册。保留旧覆盖项中仍有效的细节，已被本次明确选择替代的相冲突项须更新，避免元数据与 SVG 不一致。缺省半径来自本规范，若记录实际值则与路径一致。

`dependencies` 沿用“技能内相对路径 → SHA256”映射，增加本规范摘要，保留原 common/type/SPEC/tokens/example 依赖摘要。固定视觉编号仍绑定原 profile 资源；复绘所需的完整依据是该 profile 与独立线条选择，不将组合伪造为新视觉版本。

## 7. 验收与常见错误

绘制或切换线条后，至少检查：

- 图种、视觉完整名称或固定编号、线条 ID 三者均正确；未指定时按元数据和默认值恢复，未知值明确报错。
- 同一小型模型的三种线条都保留可直连边；必要转折分别是直角、真实圆角、平滑曲线，布局变化有实际避障依据。
- 圆角 SVG 包含真实 `Q`/`A`；半径 `18` 或按短段缩小，外侧汇流拐角一致，内部 T 接点连续。
- 曲线的端点和切线正确，无回折和尖点；线条、箭头、标记均不穿节点、文字或分组标题。
- 时序普通消息水平，ER 关系仍连接正确字段，箭头、虚实线与基数语义和原模型一致。
- `.diagram.json` 的 `line_style.id/version/source`、实际覆盖及规范 SHA256 与交付图一致；视觉 profile 与旧编号绑定未改写。
- 逐边记录 `B / L / C` 及已比较的可行方案；按最小弯折 → 最短路径 → 最少交叉取优，采用非直连方案时有取舍依据，模型弯折数与 SVG 路径一致。
- 所有剩余交叉点均有真实 `A`/`Q` 圆弧桥与「跨线不连接」图例；桥不碰文字、节点或其他桥，消除交叉后无残留桥弧。
- 含基数语义的关系线，线旁标签同时给出关系名与基数比例；未知基数写「基数待确认」，不把基数只放在注记卡。

常见错误：用圆描边假装圆角、为体现样式强制绕行、只圆分支而遗漏外侧汇流角、修剪 T 形接点导致断线、把普通时序消息弯曲、把 ER 标记或端口丢失、仅保存视觉编号而遗漏独立线条元数据；以及为减少交叉增加绕行、用跨线桥跳过弯折/长度比较、省掉剩余交叉的圆弧处理、把基数比例只集中到注记卡、模型与 SVG 的弯折数不一致。
