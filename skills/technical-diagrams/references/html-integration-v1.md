# HTML 集成契约 v1

先定位目标 figure 与它所在的 h2/h3/h4，记录原图和相邻目录项。只改被要求的图，不重新生成其他图或业务正文。新版本路径按用户要求；原地改前保留可恢复副本并检查源文件未被其他程序更改。

图以独立 SVG 内嵌，建议 `figure.diagram > .diagram-viewport > svg`；图题在 figcaption。选择器 ID 使用唯一图名，不重复占用标题锚点。宽度 100%、高度自适应，不能通过固定高度压扁 SVG。长图支持全屏适屏/适宽与平移，导出克隆 SVG 要保留 viewBox、独立样式和 marker。

目录链接指向标题，不放到错误的章节结尾。正文二级/三级编号不因插入一个 h4 子项重复使用；子项靠缩进表示归属。验证所有目录目标存在且唯一，并按 DOM 实际顺序单调排列；测试平滑滚动时等待位置满足条件后再断言定位。

交付前在无网络依赖条件下打开实际文件，核对图显示、目录定位、全屏关闭/缩放及 SVG/PNG 下载。比较其他 figure 的源内容或摘要确认局部修改范围；脚本检查不是截图视觉核对的替代。

## 单文件交付

HTML 是默认独立完整的交付单元，不依赖旁边的图片、SVG、JSON、字体或脚本文件，也不依赖 CDN。所有图形内嵌 SVG，样式和交互脚本内嵌；复绘模型放在 SVG metadata 或内嵌 JSON 中，保留 profile、模型、线条及规范版本与依赖摘要。内嵌 JSON 应正确转义 `</script>` 等结束标签。只有用户明确要求独立图源或多文件时，才另外导出附属文件。

原地修改前，在交付目录之外的工作目录 `.data-cache/` 保留可恢复副本并记录来源摘要；写回前复核来源未被外部修改。完成并验证后按运行规则清理临时文件，不把备份、QA 截图或调试产物当作额外交付。

## 通用布局验收（所有图种）

适用于独立 SVG 及 HTML 内嵌图。固定视觉 profile 和 line_style 继续沿用；以下规则控制实际布局质量，不把本次任务的坐标或间距写成所有风格的固定 token。

### 先调整布局与端口，再接受绕行

- 在语义、系统归属、文字可读和安全净距等硬约束成立的前提下，按 `line_spec_path` 的量化顺序逐边比较：先取最小弯折数 `B`，`B` 相同时取最短路径 `L`，仍相同时取全图最少交叉数 `C`。共线直连 `B=0` 且长度最短，优先采用。减少交叉不得以增加弯折或路径长度为代价；不得以「已加跨线桥」跳过 `B`/`L` 比较，也不得用桥掩盖本可通过换端口、移节点消除的绕行。
- 不把既定端口当成唯一选择。相邻卡片的水平投影有重合时，比较上／下端口直连；垂直投影有重合时，比较左／右端口直连。采用符合交互或引用含义、且不穿字穿框的端口，不为绕行增设无业务含义的中转节点。
- ER 图的多条相反方向引用先比较字段展示行。允许把对应引用字段与目标字段排在相同高度，从字段行的边界端口直接连接；同步保存展示行和端口模型，注明只是图中展示顺序调整。DDL、字段集合与约束、关系方向、条件及基数不变；不能为了直线把引用改接到标题或其他字段。
- 按量化顺序比较后仍存在的交叉，一律用所选交互规范的真实圆弧桥处理；真实汇流保持连续。消除交叉后同步删除多余桥弧、衬线和已不适用的跨线图例。桥只做局部消歧，不改变所选线条样式。
- “最短”不等于把节点贴紧。连接通道须容纳箭头、标签及其周围留白；目标是满足可读性的最短可行路径，而不是牺牲阅读空间的最短几何距离。

### 按真实尺寸计算间距与标签

- 先完成字体度量、换行和真实形状包含检查，再布局。同行节点用共同端口中心线对齐；需要等高的同类卡片按实际最大高度扩容，不强行将不同形状等高。
- 后一行的位置从上一行实际最大底边加净间距计算；内容、字号或宽度变化后重算受影响的行、端口和标签。禁止节点自动增高而仍保留旧中心间距、旧标签坐标。
- 标题带和第一行正文节点之间留独立空白；判断间留足连接线和条件文字空间。按当前字号、箭头和最终显示比例选择净距，可用若干行高作起点；不得把某张参考图的绝对坐标用于所有图，也不为侧向结束分支无谓拉长主链。
- 标签从当前路径的空白区定位：直线按其空闲段安排，转角标签避开弧段；是／否放在对应出口的通道内。两条平行请求／返回分别有文字区域，不把旧标签留在扩高后的菱形中。

### 验收必须覆盖节点和端点

- 检查节点之间的真实形状或保守外框是否碰撞，连线是否反向或退回节点；不能仅检查画布越界，也不能把源／目标节点完全排除在相交检查之外。
- 每条线的首段从源端口向外，末段从目标端口外侧进入，端点准确落在实际边界上；圆角切点、箭头和条件文字均有安全距离。
- 逐边比较是否可通过其他合理端口、邻接位置或 ER 展示行降低 `B`／`L`／`C`，记录已比较方案及其指标结果；采用非直连方案时写明取舍依据。图形模型和实际路径同时更新，模型中的弯折数须与 SVG 路径一致。核对业务模型时忽略纯几何及展示顺序差异，保留所有真实字段、动作、条件与引用。
- 渲染后检查全图和密集区域。`render_svg.mjs` 当前检查文字边界、文字重叠、连线穿字及外链；它没有自动证明节点不相碰、端点方向正确或路径最短。这些项目需补充模型／SVG 检查或人工核看，不把一次 `--strict` 通过等同于全部布局验收完成。

## 流程图排版验收

- **先定归属**：模型为节点记录 owner；泳道标题来自真实模块或系统，阶段说明另列。标题、边界与节点均留独立空间，同层泳道和同类节点保持网格对齐；不能为了视觉整齐伪造模块、把外部系统纳入内部，或把“失败分支”当成责任泳道。
- **节点读法**：标题是一句行为总结，正文是若干无序要点；长要点换行后对齐正文首字，不对齐项目符号。按字号、字体、行高和列表间距度量宽高；检查每条要点及其符号都在矩形或菱形内。判断条件仍写在对应出口，不能只放到远处说明。
- **就近分支**：先把判断的各场景节点分别放在对应方向，再选择上／下／左／右端口。可水平直连的节点按端口中心线对齐；主链紧接下一动作，不为侧向终止分支预留整块空行。一个条件的结果不应全部堆在同一列，再让其他出口绕过前一个结果框。
- **逐边比较**：检查“当前布局是否已有更短直线”“换一个合理端口是否能少一次转折”“移动节点后是否能取消长外绕”，并按最小弯折 → 最短路径 → 最少交叉的字典序取优、记录比较结果。装饰性标题和分隔线不是整幅不可穿越障碍，应调整标题留白；不能把它们当理由让主流程绕完整块画布。布局、端口、标签与连线联合调整，不能只对已定位置执行自动寻路。
- **圆角与汇流**：共线无障碍保持直线；必要的折角才用真实 Q/A 圆角。分支出口分开，真实汇流明确连接；无关线路不可直接相接。比较弯折数与路径距离时同时检查语义、障碍及可读性，不为省一弯制造远距离大绕行。
- **验收依据**：渲染后核看泳道归属、分支、长文字和密集连线。自动检查越界、重叠和穿字之外，还应逐边核对端口、直连替代路径、弯折数与不必要的绕行；“静态几何检查通过”不代表已满足就近和最少弯折原则。

## 泳道内容、标题与真实形状

带泳道的新流程图通过 FC-03（浅色分区）或 FC-04（深色标题）选择视觉；两者仍使用 flowchart 语义，线条几何独立选择。颜色、标题层级和边界尺寸只读取本次解析出的 SPEC 与 tokens，不将一套风格的颜色作为所有泳道的全局默认值。

- 模型中为每个节点记录 owner 和 lane，并为 lane 记录真实归属标题。系统名与职责说明分层，标题带等高且顶部对齐；调用、处理、协作等角色配色由本次实际归属确定，不能从示例虚构系统。
- 浅色分区风格用深蓝文字、浅色标题与淡色泳道底；深色标题风格用高对比白字标题带和白色正文。深色标题的主副文字均验收对比度与边界，不能只让主标题清晰、次标题灰淡难读。
- 节点维持“一句话行为总结＋无序要点”，长要点采用悬挂缩进。长图保留每个节点的模块标签，使阅读中段时仍可判断归属；不要反复插标题带阻断主链。
- 矩形和菱形使用各自的真实形状包含检查。实际字体的标题、模块标签、正文和项目符号的边界角点均须位于形状内；可用 SVG isPointInFill 或等价几何检查。不能把“未越出画布”或“未越出外接矩形”当成菱形通过。
- 圆角只是必要转角的外观。先调整邻接位置、主轴与条件出口，使共线且无障碍的路径直接连接；端口中心对齐后再验证弯折数与距离。不能固定所有线从底部出发，也不能为了侧向结束分支拖长主链。
- 视觉换版保留模型、owner、lane、条件、节点及连接关系；有意改变布局几何时单独记录覆盖项。HTML 始终内嵌图源、样式、脚本和复绘模型，不因泳道样式新增附属文件。


## SQL 与其他代码块

含代码的 HTML 应保留文档现有代码主题；主题丢失时先检查实际 DOM 是否匹配样式选择器。`pre.code` 的样式不会自动作用于没有 `class="code"` 的 `pre`，行内 `code` 的底色也不能代替整块容器。

代码块使用独立类，明确整块背景、内边距、等宽字体、行高和横向滚动；子 `code` 重置行内背景、边框和留白。下面仅是可随文档主题调整的通用起点，不是视觉风格的固定配色：

```html
<pre class="code-block"><code class="language-sql">SELECT label FROM shape;</code></pre>
<style>
pre.code-block {
  display: block;
  padding: 20px 24px;
  overflow-x: auto;
  background: #0f1b28;
  color: #d8e4f0;
  border-radius: 10px;
  font: 13px/1.8 Consolas, monospace;
  white-space: pre;
}
pre.code-block > code {
  padding: 0;
  border: 0;
  background: transparent;
  color: inherit;
  font: inherit;
  white-space: inherit;
  word-break: normal;
  overflow-wrap: normal;
}
</style>
```

- 需要语法高亮时本地生成并内嵌，不能依赖 CDN；样式重置不得抹掉高亮 span 的颜色。
- 高亮、加类和换主题前后逐字符比较代码文本。用户明确要求的标识重命名单独核验，不能因美化重写 SQL 或补造 DDL。
- 用实际浏览器检查容器及子元素的计算样式、长行横向滚动、复制文本和打印可读性；不只检查 CSS 是否存在。打印可采用独立浅色和换行策略，不影响屏幕上的原文。
- 所有样式、图形及必要脚本继续内嵌到单个完整 HTML；页面的按需导出功能不等于额外交付附属资源。
